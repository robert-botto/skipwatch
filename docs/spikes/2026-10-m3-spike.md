# M3 spike: platform behaviour on the free route and treg (2026-10-09)

Package M3-A of `docs/superpowers/plans/2026-10-09-skipwatch-m2-m4.md`. yt-dlp 2026.8.19,
treg CLI 0.22.0, no cookies and no logins anywhere. Every media file fetched was deleted
right after it was measured; no call ids, result ids, media URLs or tokens are recorded here.

## Contradictions with the plan (orchestrator decision before M3-B and M3-C)

1. **X `info["id"]` is the media id, not the post id.** For G2 yt-dlp returns id
   `1498418617284767747`; the post is `1505892984658743300`. M3-B's
   `canonical_url = f"https://x.com/i/status/{id}"` would point at nothing. Take the post id
   from `webpage_url`.
2. **A text-only X post that links or quotes a video post is a video to yt-dlp.** The G2
   author's reply "Previous tip:" plus a status link returned the linked post's 76 s video
   (`x/link-to-video-post.info.json`), with no error. Only a post with no media and no link
   card gives "No video could be found". M3-B must decide whether such a bundle is the post's
   own video.
3. **`anyapi.instagram.post.detail` has no caption text field** (and no duration). The
   caption only comes from the free route (`description`). M4-A cannot fill Instagram post
   text from treg with this endpoint.
4. **`anyapi.facebook.post.detail` exposes no media URL** for a public video post
   (`videoId` null, `image` empty, `durationSeconds` 0). treg cannot be the Facebook media
   fallback. (The plan expected this from the catalog example; now confirmed.)
5. Not a contradiction, a confirmation: public X video **does not need cookies**, and every
   treg media URL returned (X, TikTok, Instagram) downloaded with a plain GET.

Facebook choice: `https://www.facebook.com/gov.sg/videos/10154383743583686/`, "What to do

yt-dlp extractor test URL, so it is likely to stay reachable. Page listings such as
`/FacebookforDevelopers/videos` are "Unsupported URL" in yt-dlp, and search engines index few
Facebook video URLs, which is why a known stable URL was used.

## Privacy handling

treg responses went through `scripts/scrub_fixture.py`, then a second pass: media and image
URLs cut to scheme and host, regional CDN node names replaced with `scrubbed`, `resultId`
zeroed. In the comments fixture, people other than the post author have placeholder handles
(`replierN`), names, post ids and URLs, and unknown `@mentions` became `@someone`. yt-dlp
fixtures had regional CDN node names scrubbed the same way. A scan of every added line,
percent-decoded twice, found no public IPs, no emails, no CDN node names, no query tokens and
no call or result ids.
